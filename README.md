### Шаг 5. Broken

Метод `Broken` приводит к `StackOverflowException`, потому что метод не имеет условие выхода, что приводит к бесконечной рекурсии. Стек не очищается, так как ни один из предыдущих вызовов не завершается. 
Для того, чтобы выполнить код внутри блока `catch`, среде выполнения нужно выделить новый фрейм вызова для обработчика ошибок, но свободного места на стеке нет совсем.


## Часть 4. Самостоятельная рекурсия

### Задача C. Найди ошибку в рекурсии
1. В коде ниже в рекурсивном вызове параметр `n` не изменяется, из-за этого метод не достигнет базового случая
```csharp
int Sum(int n) {
    if (n == 0)
        return 0;

    return Sum(n);
}
```

2. В коде ниже шаг рекурсии `n + 1` увеличивает `n`. Если изначальное `n > 0`, оно будет расти и никогда не достигнет `0`, что приведет к переполнению стека. (Для отрицательных `n` рекурсия бы завершилась)
```csharp
int Sum(int n) {
    if (n == 0)
        return 0;

    return n + Sum(n + 1);
}
```


## Контрольные вопросы

**ПР8. Ответы на контрольные вопросы**
1. Базовый случай - это условие, при котором метод прекращает вызывать себя. Чтобы проверить приближается ли к нему вызов, нужно посмотреть есть ли у рекурсии шаг (изменение параметра), который приближает параметр к условию
2. Стек образуется, т.к. "замершие" вызовы не завершают свою работу, а ждут результаты выполнения следующих вызовов, занимая своё место в стеке
3. Так происходит, потому что базовый случай - это самый последний вызов в рекурсии, от которого получает результат предыдущий вызов, а от него предыдущий и т.д. При этом так же выполняется и код (от последнего к первому вызову)
4. Цикл использует фиксированный объём памяти, а рекурсия тратит память пропорционально глубине.
Слишком глубокая рекурсия вызывает переполнение стека, т.к. каждый вызов сохраняется в памяти и ждёт, когда ему передастся результат следующего
5. Необходимо посмотреть на условие завершения рекурсии и шаг рекурсии, их наличие и правильность
